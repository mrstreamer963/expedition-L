## Context

Сейчас колонисты не отслеживают занятость тайлов — `Tile` хранит только тип и проходимость. Pathfinding блокирует позиции других колонистов однократно (snapshot при поиске), но runtime-проверок нет. Два колониста могут стоять на одном тайле.

## Goals / Non-Goals

**Goals:**
- Запретить двум колонистам в `idle`/`working` стоять на одной клетке
- Разрешить walking колонистам проходить сквозь других
- Отменять job, если конечный тайл занят (jobSystem переназначит)

**Non-Goals:**
- Не добавлять "push" или "swap" механику
- Не добавлять плавное избегание (steering behavior)
- Не менять A/D панораму камеры или систему билдингов

## Decisions

- **Данные занятости на `Tile`** — добавить `occupantId: string | null` прямо в интерфейс `Tile`. Это проще отдельной Map и не требует синхронизации.
- **Жизненный цикл** — занятие/освобождение через хук в `colonist.ts` при смене `state`. При переходе в `walking` → освободить тайл. При переходе в `idle`/`startJob()` → занять тайл (если свободен).
- **Проверка в `move()`** — при каждом `position = path.shift()` брать `path[path.length-1]` (final tile) и проверять `map.tiles[y][x].occupantId === null`. Если занят — `cancelJob()`, переход в `idle`.
- **Pathfinding** — убрать всех walking колонистов из occupied set. Блокировать только если target tile занят `idle`/`working` колонистом.
- **Альтернатива рассмотрена — отдельный `OccupancyMap` класс** — избыточно для 3 колонистов на карте 30×20. Прямое поле на `Tile` проще.

## Risks / Trade-offs

- **Rare race condition** — два колониста прибывают на один тайл в одном тике. Первый займет, второй отменит job. Это корректное поведение.
- **Deadlock маловероятен** — jobSystem назначает задачи каждые 2 секунды. Если цель занята, pathfinding вернет пустой путь и jobSystem выберет другую цель.
- **Производительность** — `path[path.length-1]` это O(1). Проверка `occupantId` на каждом шаге — константа.
