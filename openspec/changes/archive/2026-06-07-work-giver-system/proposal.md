## Why

Сейчас назначение задач децентрализовано — каждый колонист в `tryAssignJob()` сам решает, какую задачу взять из `buildQueue.peek()`. Это приводит к дублированию: несколько колонистов могут быть назначены на одну и ту же стройку/еду/кровать, потому что нет центрального реестра "кто что уже взял".

Нужна система WorkGiver по образцу RimWorld:
1. Централизованный сбор всех доступных задач на карте
2. Резервирование задачи за конкретным колонистом
3. При отмене/прибытии — задача снова доступна

## What Changes

- Создать класс `WorkGiver`, который в каждом тике собирает все доступные задачи на карте (стройки)
- Добавить `TaskPool` — единый пул задач с флагом `reserved`
- Заменить `tryAssignJob()` на тиковый вызов WorkGiver для каждого колониста
- WorkGiver управляет ТОЛЬКО задачами стройки (build queue). Поиск еды и отдыха — автономный per-pawn, центральная система отключается
- Когда колонист голоден или хочет спать, он переходит в режим самообеспечения: сам ищет ближайшую еду/кровать, сам резервирует (через occupantId на тайле), идет к ней
- При `cancelJob()` / прибытии — задача освобождается
- Удалить `isNearestColonist()` — больше не нужен (WorkGiver сам распределяет)

## Capabilities

### New Capabilities
- `work-giver`: Централизованная система сбора и распределения задач между колонистами с резервированием

### Modified Capabilities

- `unit-tile-occupancy`: Добавить взаимодействие с WorkGiver — при отмене задачи (occupied target) задача возвращается в пул

## Impact

- `src/game/colony/workGiver.ts` — новый класс (scan + reserve + release)
- `src/game/colony/jobSystem.ts` — удалить `tryAssignJob()`, `isNearestColonist()`, `assignBuildJob()`. Заменить на вызов WorkGiver
- `src/game/colony/colonist.ts` — `cancelJob()` должен вызывать `WorkGiver.release()`
- `src/game/gameWorld.ts` — подключить WorkGiver в update
- `src/game/world/map.ts` — без изменений
